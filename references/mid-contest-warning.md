# 赛中预警与纠偏指南（红警信号 / 决策树 / 砍复杂度）

> 定位：数模最大的翻车不是不会做，而是**卡在一个死胡同里不肯出来，直到时间耗尽**。本文件给出一套"赛中仪表盘"——哪些信号一出现就该立刻警惕、何时果断换模型/换数据、怎么安全砍复杂度保可交付。这是 `timeline.md` 红警线的落地操作版，直接服务支柱一（逻辑严谨）与"能交出去"这个底线。

## 一、赛中仪表盘：三类红警信号

**每 4–6 小时对一次表**，命中任一条就进入「纠偏流程」（见第三节），别硬扛。

### A 类 · 求解卡死（最致命）

| 信号 | 说明 | 处置 |
|---|---|---|
| 同一模型调了 >3 小时还没出结果 | 收敛不了 / 报错 / 数值炸了 | 立即换求解器或换更简单模型 |
| 误差 / 残差无限大或 NaN | 发散 | 查量纲、初值、步长，先跑通"能出数" |
| 结果量级明显不对 | 如预测亿级人口 / 负续航 | 先过 `sanity_check.py`，再查模型逻辑 |
| 代码 bug 修了 1 小时没定位 | 陷进去了 | 换人排查 or 砍掉该问先做下一问 |

### B 类 · 数据/假设翻车

| 信号 | 说明 | 处置 |
|---|---|---|
| 关键数据拿不到 / 字段对不上 | 数据不可得 | 换数据源 / 换题（若还在开题期） |
| 某个假设被实测数据打脸 | 假设不自洽 | 修假设或显式标注失效边界 |
| 清洗后样本量骤减 | 缺失/异常过多 | 检查清洗是否过度，必要时保留样本 |

### C 类 · 节奏/产出失控

| 信号 | 说明 | 处置 |
|---|---|---|
| 第 2 天晚还没跑通全部问（国赛）/第 3 天（美赛） | 进度落后 | 进入「砍复杂度」流程 |
| 一个问做到 80% 还在磨"完美" | 完美主义 | 先交 80% 版本，剩 20% 看时间 |
| 队友分工重叠 / 在等对方 | 协作断裂 | 立即重分任务，别空等 |

## 二、红警信号优先级

**A 类（求解卡死）> C 类（进度）> B 类（数据/假设）**。先救最耗时的求解问题，因为它是进度落后的最大来源；数据问题多数时候可以用"显式标注假设"绕过，不必换题。

## 三、纠偏决策树（命中信号后照走）

```
命中红警信号
   │
   ├─ 还剩多少时间？
   │    ├─ < 6h → 只保"能交"，砍到每问一个最简可靠模型（见砍复杂度）
   │    ├─ 6–18h → 尝试一次"换模型/换求解器"，保留当前可用的版本作退路
   │    └─ > 18h → 可以系统性排查，但设 2h 上限，超时降级
   │
   ├─ 问题在求解器？ → 换求解器（linprog→milp→differential_evolution），或换初值/步长
   ├─ 问题在模型太复杂？ → 降复杂度：线性化 / 忽略次要项 / 单目标化
   ├─ 问题在数据？ → 换数据源 or 显式标注"该假设失效边界"
   └─ 问题在"这问本来就难"？ → 砍次要小问，保主干四问完整

降级后：旧结果存档（git 提交 or 改名 .bak），新结果跑通后先对表 sanity check 再进论文。
```

**关键心法**：纠偏的核心不是"找到最优解"，而是**"保证在截止前有一条完整、可信、可复现的结果链"**。最优可以留到赛后，交得出去才是当下的目标。

## 四、砍复杂度决策树（怎么安全地"砍")

砍的不是质量，是"复杂度"。优先级从低到高砍：

1. **砍次要小问 / 附加题**：主四问保完整，第 5/6 问（若有）砍到一句话结论 + 指向主模型。
2. **砍模型族复杂度**：换更简单但可靠的模型（LSTM→回归；遗传→differential_evolution；多目标→ε-约束单目标扫描）。
3. **砍特征 / 参数**：只留对结果影响最大的 2–3 个参数（可用 `sanity_check.py` 或敏感性先筛），其余固定。
4. **砍精度**：网格从细到粗；MC 次数从 10^5 降到 10^4（报更大置信区间）；步长放宽。
5. **砍求解完整性**：先给一个"用简单模型跑出的完整结果"，复杂模型作为"展望/改进"写进局限。

**砍完必做**：砍掉的每一项，要在论文「模型评价与展望」里显式说明"本可用更复杂模型，为时间/数据所限采用简化，并讨论了其影响"——**诚实标注比硬撑一个跑不出来的"高级"模型更得高分**（呼应支柱一的诚实负结果）。

## 五、赛中节奏卡（配合 `timeline.md` 用）

| 时刻 | 自检 |
|---|---|
| 开赛后 4h | 定题了吗？每问"求什么/给什么/交付什么"写清了吗？ |
| 第 1 天末 | 数据 clean 了吗？假设列了吗？每问基线模型想好了吗？ |
| **第 2 天末（国赛）/第 3 天末（美赛）** | **全部问都跑通了吗？没有就立即砍复杂度** |
| 交稿前 6h | 只做检验/论文/降重/参考文献，**不再做新计算** |
| 交稿前 2h | 数值对账 + sanity + 格式 + 参考文献核验 |

## 六、交稿前"还能救"的 3 件事

> 心法先立住：**论文完整 > 论文完美**——完整 + 排版美观 + 摘要带数字，即使个别结果不完美也有获奖机会（美赛社区共识，国赛同理）；反之"半成品的高级模型"最危险。卡住的地方：能写进假设的写假设，能写进局限的写局限，别硬撑。

- **数字全对表**：用 `sanity_check.py` + `check_results.py`，论文里每个数都能回溯。
- **摘要补数值**：摘要缺数字是最大失分点，花 30 分钟把每个结论填上具体数。
- **诚实标注局限**：凡是"没做到/简化了"的地方，主动写进评价与展望，别藏着被评委挑。

## 七、自检清单（赛中每阶段过一遍）

- [ ] 当前在跑的每个模型，是否都有"能出数"的可用版本？
- [ ] 有没有陷在同一个 bug / 模型超过 2 小时？
- [ ] 进度是否对齐 timeline 红线（第 2/3 天末跑通）？
- [ ] 砍掉的复杂度是否已在论文里显式标注？
- [ ] 是否有一个"保底完整方案"随时可交？
