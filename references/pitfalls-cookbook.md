# 错题本 · 数模常见翻车实录（pitfalls-cookbook）

> 目的：把历年真实翻车点按「症状 → 真实案例 → 后果 → 正确做法 → 对应 skill 资源」编排，**每条都能独立对照自查**。赛前扫一遍、赛中挂在手边、交稿前逐条勾。本册与「质量三支柱」「铁律」一一对应，是它们的"反面教材版"。

## 一、逻辑严密性翻车（对应支柱一）

### P1 假设与模型"两张皮"
- **症状**：假设列了一堆，但模型里根本没用到；或模型用了"忽略 XX 影响"的简化，假设表里却没写对应条目。
- **真实案例**：假设写"忽略温度影响"，结果模型里温度项又被塞进去当特征——双向对不上，评委一眼看出论证链断。
- **后果**：论证链断裂，直接判"建模不完整"，逻辑分腰斩。
- **正确做法**：每条假设要在模型里真的被用（或真的被简化掉），模型里每个简化都要在假设里有对应条目（双向可追溯）。见 `assumptions-justification.md` 三件套。

### P2 结论跳步
- **症状**："由结果良好，故本方案优越""模型精度高，因此建议可行"。
- **后果**：缺中间推理，逻辑严密性直接扣分（支柱一核心要求：每步都能回答"凭什么走到下一步"）。
- **正确做法**：补出"结果 → 机制解释 → 结论"的链条，敢写反例与负结果并给机制解释，比报喜更显严密。

### P3 量纲 / 量级灾难
- **症状**：把百分比当小数（写 85 实为 0.85）、kW 当 W（差 1000 倍）、概率放进 [-1,1]、权重和 ≠ 1 却当概率用。
- **真实案例**：2026 某电池题把 SOC 百分比直接当 0–100 数做 ODE，量级错导致曲线全平。
- **后果**：所有相关数字全错，铁律二（数值可回溯）直接破防。
- **正确做法**：数值进论文前先过 `scripts/sanity_check.py`（量纲/量级/边界自动校验），权重和=1、概率∈[0,1] 由脚本兜底。

### P4 边界 / 退化条件错
- **症状**：ODE event 函数签名漏写 `args`，或退化情形（某参数→0）没验证公式还能用。
- **真实案例**：`solve_ivp(..., events=hit, args=(k,))` 但 `def hit(t,y):` 没接 `k` → `TypeError: takes 2 positional arguments but 3 were given`。见 `advanced-methods-templates.md` §9 修正版。
- **后果**：求解崩溃或事件永不触发，结果静默错误。
- **正确做法**：event 函数签名必须含 `args`；退化情形单独跑一遍验证公式连续。

## 二、创新性翻车（对应支柱二）

### P5 堆模型不择优
- **症状**：列了 5 个模型，但没对比、没选、没融合，像零件拼盘。
- **后果**：假创新，反而扣分——亮点 = 有用 + 可检验 + 对结果有实际贡献，三者缺一即"假创新"。
- **正确做法**：多模型对照 + 择优/融合（最稳的亮点套路），每问落点先查 `innovation-playbook.md` 套路表，**创新是设计出来的，不是写完再找的**。

### P6 黑箱 ML 替代机制
- **症状**：美赛 A/C 题直接上随机森林/神经网络当主模型，无物理/统计机理支撑。
- **真实案例**：2026 MCM A（电池 SOC）官方要求必须有显式连续时间模型（纯拟合黑箱、无连续时间方程的不满足要求）；C 类（星舞）要求统计逆问题+可解释，纯拟合黑箱会被判"无建模"。
- **后果**：直接低分甚至淘汰。
- **正确做法**：用"观测 = 潜在真实 + 噪声"的可解释统计推断框架（见 `bigdata-playbook.md`、`worked-example-2026-mcmC.md`），ML 只做辅助/对照。

### P7 "口嗨区间"
- **症状**：论文写"95% 置信区间 [a,b]"或"Bootstrap 检出率 0.9x"，但代码里根本没有这段统计。
- **后果**：铁律二违规（每个数字必须能回溯到代码）。
- **正确做法**：代码里没有的统计量，要么删、要么补代码，禁止手编区间。

## 三、论文质量翻车（对应支柱三）

### P8 摘要空泛无数值
- **症状**："本文提出一种有效的方法解决了该问题"——四要素（问题—方法—结果—结论）里"结果"没有任何具体数字。
- **后果**：**缺数值的摘要等于没写**，评委 30 秒定档直接掉档。
- **正确做法**：摘要带具体数值（如"Spearman≈0.82""共 2 个不同冠军翻转"），见 `figures-and-abstract.md`、`english-writing-mcm.md`（Summary Sheet 四句式）。

### P9 图表三件套缺失
- **症状**：图无标题/无单位、DPI 低、正文从未引用该图、图注不能独立传达结论。
- **后果**：观感差，figcheck 不过，拖累整篇评分。
- **正确做法**：每张图配「引出句 → 图表 → 解读句」，图注独立可读；提交前跑 `scripts/figcheck.py`。

### P10 大段抄题面
- **症状**：问题重述整段复制原题。
- **后果**：被查重、判"无自己的分析"扣分。
- **正确做法**：转述不抄题；提交前跑 `scripts/dedup_scan.py` + 过 `writing-deai-dedup.md`。

### P11 文献编造
- **症状**：编不存在的论文/书籍、凭记忆填 DOI、文献表有"孤儿条目"。
- **后果**：**学术不端一票否决**；铁律一明令严禁。
- **正确做法**：先联网核实（PubMed/DOI/出版社）再引用，交稿跑 `scripts/verify_refs.py` 逐条过。

## 四、赛种规则翻车（对应铁律三）

### P12 超页数 / 算错页面预算
- **症状**：美赛**全文 25 页硬上限**（Summary Sheet + TOC + 正文 + 参考文献 + 附录 + 代码，历年通行口径），AI Use Report 不计入，但很多人忘了附录和代码也占页。
- **后果**：超页直接拒收。
- **正确做法**：动笔前按 `rules-and-deadlines.md` 做页面预算，附录/代码单列规划。

### P13 沿用往年规则印象
- **症状**："去年也是 20 页/不查 AI"——每年页数、AI 披露、查重口径都在变。
- **后果**：违规、提交了才发现格式不对。
- **正确做法**：铁律三——**先确认当年规则再动笔**，绝不沿用印象。

## 五、复现翻车（对应铁律二）

### P14 随机种子没固定
- **症状**：代码里 `np.random.rand()` 没设 seed，或不同段落用了不同 `seed`。
- **后果**：canonical 复跑对不上，数字前后矛盾。
- **正确做法**：凡随机一律固定 `seed=0`；交付前固定 seed 全链重跑逐位核对。

### P15 改一个数字没 grep 全目录
- **症状**：把某结果从 28 改成 12，只改了摘要，表格/图注里还是 28。
- **后果**：论文内部前后矛盾，评委质疑口径。
- **正确做法**：改数字必全目录 `grep` 旧值，零残留才算改完（铁律二·3）。

## 六、求解实现翻车（代码层）

### P16 CVaR 线性规划无界
- **症状**：目标写成 `mean - kappa*VaR` 且 `VaR` 无下界 → "Linear relaxation unbounded"。
- **真实案例**：`advanced-methods-templates.md` §6 原始版就崩过，修正为 `VaR=LpVariable('VaR', lowBound=-5.0)` + 标准 CVaR 目标 `kappa*(VaR + 1/((1-alpha)*S)*sum(loss))`。
- **后果**：求解失败，整段风险优化交付不了。
- **正确做法**：直接用修正版模板，别自己改目标式。

### P17 数据泄露（过拟合假象）
- **症状**：训练集里混入了测试集信息；或同一组样本同时出现在训练/测试折（如按行切分但同用户有多行）。
- **后果**：指标虚高，实战一用就崩，评委若敏感会判"检验不可信"。
- **正确做法**：按组切分用 `GroupKFold`（见 `code-templates.md` §11），训练/测试严格隔离。

### P18 相关性当因果
- **症状**：两变量高相关直接下"X 导致 Y"的因果结论，无任何识别策略。
- **后果**：结论不可靠，机制题致命伤。
- **正确做法**：用 DiD / 反事实重放做识别（见 `advanced-methods-templates.md` §3、§10），并解释"为什么能归因"。

## 七、赛中节奏翻车

### P19 第 2 天晚还没跑通全部模型还不砍复杂度
- **症状**：钻牛角尖在一个复杂模型上，全链其它模型都没跑通。
- **后果**：交不出可交付物，比"简单但完整"更糟。
- **正确做法**：触发 `mid-contest-warning.md` 红警即砍复杂度保可交付；赛程红线见 `timeline.md`。

### P20 跳过强制确认门禁
- **症状**：一键生成全部成果、模型选型不给用户选。
- **后果**：方向错了全白费，且违反最高优先级铁律（不可解锁）。
- **正确做法**：始终多方案先行、用户拍板才执行；用户说"全自动"也仍须逐项给方案。
