# 评委视角手册（评阅要点对齐 · 裁判预演）

> 定位：**设计期对齐评委口味 + 交稿前 30 分钟裁判预演**。评委在双盲评审下短时间内读海量论文，得分逻辑是四件事——**看得懂、找得到、信得过、用得上**。本文件把历年官方《评阅要点》里的通用信号提炼成可执行动作，把"评委怎么想"变成建模和写作时的自查项。
>
> 来源说明：评阅要点每年随赛题公布（官方展示站 dxs.moe.gov.cn、数学中国 madio.net 等有整理，见 `cumcm-years.md`）；本文提炼的是**跨年份稳定的通用信号**，题相关细则以当年原文为准。

## 一、动笔前：先把当年评阅要点找出来（开题 2h 内）

1. `web_search` 检索「`<年份> 高教社杯 <题号> 评阅要点`」与命题人/命题组解读文章；
2. 找不到当年的，找**同题型最近一年**的评阅要点（如 A 机理题看 2025A、C 数据题看 2023C；题型号定位以 `cumcm-years.md` 为准）；
3. 把要点里"比较好的做法 / 应予以鼓励"类注释抄到题目分析卡上——**这些就是评分加权的落点**（各赛区在官方要点基础上自主评阅，要点=最大公约数）。

## 二、评阅要点里的 8 条通用信号（信号 → 动作）

| # | 评委信号（历年评阅要点归纳，引号内为转述、非逐字原文） | 我们的动作 |
|---|---|---|
| 1 | **快速/解析算法优于纯枚举与无脑智能算法**（"枚举法、智能算法不是好的求解方法"） | 能解析/二分/凸求解就别上启发式；**用启发式必须写清理由**（目标非凸/维度灾难）+ 对照解析法验证 |
| 2 | **简化必须给依据**（"圆柱不能简单视为一个点，但转化为少数关键点判别并给出依据是较好的做法"） | 每处几何/物理简化配一句"为什么可以"+ 验证方式（对照 `assumptions-justification.md` 三件套） |
| 3 | **论文中明确给出计算时间**（"明确给出计算时间是比较好的"） | 每问求解代码打时间戳，正文给"本问求解耗时 Xs（机器：CPU 型号）"；复杂度 O(·) 写进方法节 |
| 4 | **先缩小决策变量范围并给依据** | 优化建模先做"参数物理意义/数据边界"预筛，正文给缩小过程（这一步本身就是得分点） |
| 5 | **协同/组合/分层思路应鼓励**（"每个烟幕只遮蔽部分目标而共同遮蔽全部，应予以鼓励"） | 多对象/多阶段题主动设计协同机制；大问题用"先分配后优化"分层降维——这正是支柱二亮点 ①③ |
| 6 | **目标函数与约束要有明确数学表达**（"需明确给出目标函数的数学表达形式及决策变量范围"） | 每问一个编号的优化/统计模型式，决策变量、约束、目标逐一列全，别停留在文字描述 |
| 7 | **多算法交叉验证结果**（优秀论文常以 PSO 与差分进化互验，报告相对误差） | 主结果至少两种算法/两条路径互验，报告相对误差；这就是"信得过"的硬证据 |
| 8 | **分问作答、一一对应**（"问题-方法-结论一一对应，评委能快速抓住"） | 章节结构严格映射题目小问；摘要按问给"模型+数字+结论"（对照 `paper-skeleton.md`） |

## 三、「四得」自查（评委阅读体验的四个成本项）

| 评委成本 | 我们的对策 |
|---|---|
| **看得懂** | 每问结构：问题重述→假设→符号→模型→算法→结果→检验；首次出现的符号必在符号表 |
| **找得到** | 结论编号化（结论 1/2/3），摘要可当"导航页"用；图表三件套让评委不读正文也能懂（`paper-quality-gate.md` 关卡二） |
| **信得过** | 结果有误差量化、有检验、有交叉验证（信号 7）；敏感参数有多维灵敏度（等高线/龙卷风图，`advanced-methods-templates.md` Sobol） |
| **用得上** | 见 §四 模型应用指南——"空中楼阁"是评委对复杂模型最常见的负面评语 |

## 四、两个落地模板（写作时直接套）

### 4.1 模型对比表（每个核心模型配一张，"拉踩"要拉得有据）

| 对比维度 | 本文模型 | 备选 A（主流） | 备选 B（前沿） |
|---|---|---|---|
| 精度（RMSE/MAPE） | **本文值** | 备选 A 值 | 备选 B 值 |
| 计算效率（耗时） | 本文值 | 备选 A 值 | 备选 B 值 |
| 可解释性 | 参数有物理意义 | 一般 | 弱（黑箱） |
| 缺失数据鲁棒性 | 中 | 中 | 高 |
| 参数敏感性 | 低（±20% 稳健） | 高 | 中 |

> 要点：维度选 4–6 个、至少含精度之外的一个"业务维度"（效率/可解释/鲁棒）；对比结论必须回指"所以我们选它"——只比不选等于没比。数据全部来自 `results.json`（铁律二）。

### 4.2 「模型应用指南」小节（放在模型评价之前，半页）

1. **输入**：需要什么数据/字段/格式（给最小示例一行）；
2. **参数**：关键参数推荐取值范围与设置逻辑（对应假设里的阈值依据）；
3. **输出**：结果怎么读、每个数值列的含义；
4. **复现**：指向附录的可执行脚本与运行命令（`init_project.py` 骨架天然支持——评委拿到支撑材料就能一键跑）。

## 五、社区流传的分值结构（⚠️ 仅作自评参照，不信任记值）

> 各赛区自主评阅、无官方公开分表；以下为社区流传口径（整体印象 ~10 分 + 分问 ~20–25 分 + 检验灵敏度 ~10 分；"65 分国奖线、80+ 稳一线"之说）。**用法**：这组"流传分表"与关卡六自评**不是同一把尺**（流传口径是外部/历史印象，关卡六是 skill 自身的六维定稿标尺），别把"65=国奖线"直接套到关卡六分数上；它只用来提示**相对权重**——"整体印象"低 = 摘要/排版先崩，分问分低 = 某问模型或结果弱。真正可靠的定稿判断还是关卡六的六维评分（≥85 才定稿）。

## 六、交稿前裁判预演（30 分钟，照走）

1. **只读摘要（3 min）**：假装自己只有 90 秒——四要素齐吗？数字具体吗？愿意往下翻吗？
2. **每问三连问（15 min，每问 ~4 min）**：结论是什么？凭什么的（哪条证据链）？数字哪来的（`results.json` 可回溯吗）？
3. **假设挑刺（5 min）**：哪条假设最可能被评委质疑？有辩护吗（理由+验证）？
4. **四得过一遍（5 min）**：看得懂/找得到/信得过/用得上，哪项最弱补哪项；
5. **对照信号表（2 min）**：§二的 8 条信号，逐条问"这条我做到了吗"——尤其 3（计算时间）和 7（交叉验证），这两条最容易漏。

> 预演发现的问题按严重度处理：致命（数字对不上/结论无据）→ 立即修；观感（图表/措辞）→ 列清单按剩余时间改。全程与 `paper-quality-gate.md` 关卡六联动：预演减的分计入百分制。
