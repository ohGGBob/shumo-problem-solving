# 模型适配：DeepSeek V4 Pro / V4 Flash 单模型运行预设

> 一次会话只能绑定一个模型。本页给出**两套单模型运行预设**：选定 V4-Pro 就按 Pro 预设跑（推理优先、精准加载），选定 V4-Flash 就按 Flash 预设跑（执行优先、全量加载、成本优先）。**不是同时用两个模型，而是"选谁就用谁的预设"。** 规格与价格为公开可核实信息（来源见文末），以官方价格页为准。

## 一、双模型画像（已核实）

| 维度 | DeepSeek-V4-Pro | DeepSeek-V4-Flash |
|---|---|---|
| 总参数 / 激活 | 1.6T / 49B（MoE） | 284B / 13B（MoE） |
| 上下文 / 最大输出 | 1M tokens / 384K | 1M tokens / 384K |
| 定位 | 高端推理 + Agentic Coding | 高并发、低成本、轻量任务 |
| 强项 | 复杂推理、长链论证、数学/代码、Agent 多步执行 | 速度、性价比、批量处理、长文档全量消化 |
| 延迟 / 并发 | ~800ms+ / ~500 | ~200–300ms / ~2500 |
| 参考价（元/百万 token） | 输入 ¥3（缓存 ¥0.025）/ 输出 ¥6 | 输入 ¥1（缓存 ¥0.02）/ 输出 ¥2 |
| 对 skill 的含义 | 省着用，只喂高价值推理 | 可放开用，全量喂长文档、跑批量 |

> 两款都支持 1M 上下文——长文本不是问题，**策略差异在于"贵的怎么省、快的怎么用"**。

## 二、环节推理强度画像（用于选型 / 判断何时换模型补）

下表标注每个环节的**推理强度**。注意：**主会话选定一个模型后，全部环节都由它承担**——下表的意义是：
① 选 Pro 时，高推理强度环节（选型/创新/论证）自然发挥最好；
② 选 Flash 时，高推理强度环节质量可能略降，这是它最可能"卡壳"的地方；
③ 卡壳时，知道该开新会话换 Pro 补哪一段。

| skill 环节 | 推理强度 | 说明 |
|---|---|---|
| 读题拆解、真题定位 | 低 | Flash 也能跑得很好 |
| 模型选型（给 2–3 方案 + 取舍） | **高** | 决策质量定上限；Flash 最可能卡壳处 |
| 创新点设计（支柱二） | **高** | 亮点 = 有用+可检验+有贡献，最吃推理 |
| 假设与逻辑自洽（支柱一） | **高** | 双向可追溯要严密论证链 |
| 求解代码实现 | 中~高 | 复杂算法需 Pro；`code-templates` 套模板 Flash 可胜任 |
| 结果数值落盘、批量跑 | 低 | 本地脚本承担，与模型无关 |
| sanity/对账/降重/文献等校验脚本 | 低 | 本地脚本承担，与模型无关 |
| 论文成文（摘要/论证段/设计意图） | **高** | 写作质量 + 逻辑严密双重要求 |
| 降 AI 味改写（逐条套改写库） | 低 | 对照 `deai-rewrite-bank.md` 机械替换 |
| AI 使用报告、提交清单 | 低 | 模板化 + 格式化 |

## 三、上下文与成本预算（两款都要 1M，但用法相反）

- **Pro（贵）**：**精准加载**——只读当前阶段需要的 references（按 SKILL 路由表），不整库全读；长文档用 `web_fetch` 分页/摘要，别一次塞满；把多轮对话压缩到关键上下文再喂 Pro。
- **Flash（便宜）**：**放开用**——可全量读论文/长文档、批量预处理（题干、references 汇总、日志扫描）、跑校验脚本；缓存命中价低至 ¥0.02/M，高频小任务放 Flash 最划算。
- **省 token 技巧（单会话内）**：先把长材料压缩成"结构化要点"再喂模型（尤其 Pro 会话），避免长文档整段占用昂贵上下文。

## 四、提示词策略差异

| 场景 | V4-Pro | V4-Flash |
|---|---|---|
| 难题 | 开放式多方案推导、让 DeepThink 长链验证 | 拆成短指令链，逐步确认 |
| 结构化输出 | 可要求输出论证链 + 反例 | 明确要求 JSON/表格/固定字段 |
| 批量 | 不干批量琐事 | 模板化批量执行，可并行 |
| 长上下文 | 只给高价值片段 | 可全量塞入 |

## 五、切换模型（= 开新会话）

一次会话不能热切换模型。所以"升级/降级"在实操上是：**开一个新会话、换模型、处理完该环节、把结果拿回主会话**。

- **Flash 主会话卡壳信号**：多次试错无进展 / 推理明显敷衍 / 关键取舍说不清 → 新开会话选 **Pro** 处理该环节（多为选型/创新/论证），结果带回主会话。
- **Pro 主会话浪费信号**：一直在跑机械校验、格式整理、批量改写 → 这些活本可直接跑**本地脚本**（与模型无关），无需模型承担；确需模型时用 Flash 新会话更快更省。
- **赛时建议（二选一）**：追求质量选 **Pro** 主力（贵但稳）；追求速度/成本选 **Flash** 主力，推理环节卡壳就换 Pro 补。别在两个会话间来回搬运大段上下文，尽量把"想"的环节集中到 Pro 会话一次做完。

## 六、对 skill 执行的具体适配（按本会话模型执行）

1. 开任务前确认本会话模型，按对应预设执行：**Pro 预设** = 推理优先 + 精准加载（省 token）；**Flash 预设** = 执行优先 + 全量加载（放开用）。
2. 用 `scripts/model_profile.py v4-pro` / `v4-flash` 拿到本会话模型的推荐配置（token 预算、加载策略、提示词策略）。
3. 校验脚本（sanity/对账/降重/文献/图表/AI 报告）是**本地 Python 工具，与模型无关**——任何模型会话下都直接调用，不占用模型 token。
4. 紧急模式（`emergency_run.py`）同理：脚本部分本地跑；推理环节由本会话模型承担，卡壳则换 Pro 新会话补。
