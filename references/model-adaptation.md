# 模型适配：DeepSeek V4 Pro / V4 Flash 双引擎分工

> 本 skill 默认可用 DeepSeek V4 Pro / V4 Flash 两款模型驱动。适配目标是：**让"想"交给 Pro、"做"交给 Flash**，在成本、速度、质量三者间取最优。规格与价格为公开可核实信息（来源见文末），以官方价格页为准。

## 一、双模型画像（已核实）

| 维度 | DeepSeek-V4-Pro | DeepSeek-V4-Flash |
|---|---|---|
| 总参数 / 激活 | 1.6T / 49B（MoE） | 284B / 13B（MoE） |
| 上下文 / 最大输出 | 1M tokens / 384K | 1M tokens / 384K |
| 定位 | 高端推理 + Agentic Coding | 高并发、低成本、轻量任务 |
| 强项 | 复杂推理、长链论证、数学/代码、Agent 多步执行 | 速度、性价比、批量处理、长文档全量消化 |
| 延迟 / 并发 | ~800ms+ / ~500 | ~200–300ms / ~2500 |
| 参考价（元/百万 token） | 输入 ¥3（缓存 ¥0.025）/ 输出 ¥6 | 输入 ¥1（缓存 ¥0.02）/ 输出 ¥2 |
| 对 skill 的含义 | 省着用，只喂高价值推理 | 可放开用，全量喂长文档、跑批量 |

> 两款都支持 1M 上下文——长文本不是问题，**策略差异在于"贵的怎么省、快的怎么用"**。

## 二、分工总原则：Pro 想，Flash 做

把 skill 的每个环节按"推理密度"分流：

| skill 环节 | 主力模型 | 原因 |
|---|---|---|
| 读题拆解、真题定位 | Flash | 信息整理 + 检索，不需深推 |
| 模型选型（给 2–3 方案 + 取舍） | **Pro** | 决策质量直接决定上限，需长链推理 |
| 创新点设计（支柱二） | **Pro** | 亮点 = 有用+可检验+有贡献，最吃推理 |
| 假设与逻辑自洽（支柱一） | **Pro** | 双向可追溯要严密的论证链 |
| 求解代码实现 | **Pro**（复杂）/ Flash（模板复用） | 复杂算法 Pro；`code-templates` 套模板可 Flash |
| 结果数值落盘、批量跑 | Flash | 机械执行，量大价廉 |
| sanity/对账/降重/文献等校验脚本 | Flash | 标准库脚本，谁跑都行，Flash 省钱 |
| 论文成文（摘要/论证段/设计意图） | **Pro** | 写作质量与逻辑严密性双重要求 |
| 降 AI 味改写（逐条套改写库） | Flash | 对照 `deai-rewrite-bank.md` 机械替换 |
| AI 使用报告、提交清单 | Flash | 模板化 + 格式化 |

## 三、上下文与成本预算（两款都要 1M，但用法相反）

- **Pro（贵）**：**精准加载**——只读当前阶段需要的 references（按 SKILL 路由表），不整库全读；长文档用 `web_fetch` 分页/摘要，别一次塞满；把多轮对话压缩到关键上下文再喂 Pro。
- **Flash（便宜）**：**放开用**——可全量读论文/长文档、批量预处理（题干、references 汇总、日志扫描）、跑校验脚本；缓存命中价低至 ¥0.02/M，高频小任务放 Flash 最划算。
- **混合流水线**：Flash 先把全部材料压缩成"结构化要点"，Pro 只基于要点做推理——成本与质量的平衡点。

## 四、提示词策略差异

| 场景 | V4-Pro | V4-Flash |
|---|---|---|
| 难题 | 开放式多方案推导、让 DeepThink 长链验证 | 拆成短指令链，逐步确认 |
| 结构化输出 | 可要求输出论证链 + 反例 | 明确要求 JSON/表格/固定字段 |
| 批量 | 不干批量琐事 | 模板化批量执行，可并行 |
| 长上下文 | 只给高价值片段 | 可全量塞入 |

## 五、升级 / 降级路径（自动分流）

- **Flash 卡壳信号**：多次试错无进展 / 推理明显敷衍 / 关键取舍说不清 → **该环节升级 Pro**。
- **Pro 浪费信号**：在跑机械校验、格式整理、批量改写 → **降级 Flash**。
- **赛时建议**：主问建模、创新点、摘要、论证段用 Pro；数据清洗、脚本批量、降重改写、AI 报告用 Flash。省钱同时保质量。

## 六、对 skill 执行的具体适配

1. 进入某环节前，先按第二节判断该用哪款（路由表已标注）。
2. 用 `scripts/model_profile.py v4-pro` / `v4-flash` 拿到该模型的推荐配置（token 预算、加载策略、分工）。
3. 脚本批量任务（sanity/对账/降重/文献/图表）统一交给 Flash 侧跑。
4. 紧急模式（`emergency_run.py`）下：推理环节（选型/创新/论文）默认 Pro，执行环节（骨架/校验/报告）默认 Flash。
