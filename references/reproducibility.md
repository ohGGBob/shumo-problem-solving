# 可复现性收口 + 输出治理 + 数值单一来源

> 目标：交稿时任何数字都能 5 分钟内在"干净环境"里复现出来；工作区不残留互相矛盾的结论；论文里没有"没有代码支撑的统计量"。

## 一、数值单一来源（最省心的做法）

1. 写一个 `export_results.py`（或每个脚本收敛到一个 `dump_results()`），把全部关键数字落盘成 `results.json`：Q1 的 AIC/系数/p 值、Q2/Q3 的分组边界/时点/达标率/风险、Q4 的 PR-AUC/阈值/灵敏度/特异度……
2. 论文和报告里的数字**全部来自这个 json**（可再写个小脚本把 json 渲染进 LaTeX 表格），禁止对着终端输出手抄。
3. 改代码后重跑 exporter，diff 一下 json 与上一版，逐项说明"变了什么、为什么变"，再同步文档。

## 二、canonical 验证脚本（交稿收口动作，不是可选项）

- 固定 `RANDOM_STATE=0`（或等价 seed），用同一协议把论文**全部**数字重算一遍。
- 逐位对照 exporter 输出 vs 论文正文/摘要/表格：任何一处对不上，先停下修，再继续。
- 顺带做「口径标签」核对：每张表每行是「行级 / 分组级 / 全数据」口径必须写明且表内一致（见 `preprocessing-pipeline.md` §九）。

## 三、干净环境一键复跑

1. 生成 `requirements.txt` 且**锁版本到 `==`**（`pip freeze` 后精修），不要 `>=`。
2. 交付前在**新建 venv** 里 `pip install -r requirements.txt`，全链重跑一遍（预处理 → 各问 → exporter），逐位对照论文。
3. 规避跨环境坑：
   - 树模型 / 交叉验证 / joblib 显式 `n_jobs=1` 或受控，别默认吃满核（受限/容器环境可能因多进程管道被禁而崩）。
   - 不要依赖本机绝对路径、随机文件顺序、未固定 seed 的随机数。
   - DataFrame 打印看单位：科学计数法（1.34e6）别误读成 134。

## 四、统计量必须有代码支撑

- 论文/报告里出现的**每一个**置信区间、Bootstrap 次数、误差 σ、检出率、显著性 p 值……都要有能产出它的代码。
- 写出了"95%CI [x,y]"却说不出是哪段代码算的 → 删掉，或补代码重算再写回。
- 反例：结论里写"300 次 Bootstrap 得到 CI"但仓库里没有任何 bootstrap 脚本——这是硬伤，评委/复核一眼抓包。

## 五、输出治理（workspace 卫生）

1. 平行/探索方案：命名 `experiment_<what>.py`，输出统一写 `output/_experiments/`，并在脚本头注释"用途 + 为何不用作最终口径"。
2. **探索/讨论方案允许并存，但必须标注 + 明确主次**：每个备选方案写清"用途 + 结论 + 为何不 / 为何作为最终口径"；**交付目录里"最终口径"必须唯一，且与论文完全一致**，其余进 `_archive/`。以论文为主体，其余只是讨论稿，别让评委误判"哪套才是最终答案"。
3. 图形产物控制：提交只留论文用到的 png/svg/pdf（≥300dpi），大体积的 tiff、中间 alignment/audit 之类的调试产物清出交付目录。
4. "多方法对照"**写进论文**就是稳健性论据（加分）；不写进论文的探索结果，放 `_archive/` 或标注清楚，别零散留在交付根目录。

## 六、AI 使用与诚信

- 按当年赛题要求完成 AI 工具使用披露（美赛 MCM/ICM 近年要求单独声明）。
- 只把「代码跑出来 + 检验通过」的结果写进论文；AI/模型的口头断言一律不当作结论。
- 诚信底线同 `SKILL.md`「参考文献铁律」：不编数据、不编文献、不无实证声称胜过权威方法。
