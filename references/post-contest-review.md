# 赛后复盘沉淀机制（把每次参赛变成可复用的资产）

> 定位：数模最大的浪费是**打完就忘**。本文件建立一套复盘与沉淀机制：每次参赛后 48 小时内做四维复盘，把「踩过的坑」「好用的代码/图表」「被答辩问倒的点」回流成可复用的资产，下次直接复用。配套脚本 `scripts/review_survey.py` 一键生成复盘问题清单。

## 一、为什么必须复盘（四维价值）

- **数据维度**：这次清洗踩了什么坑？缺失/异常怎么处理的？→ 下次照抄流程。
- **模型维度**：哪类题用了什么模型、效果如何？哪个模型是坑？→ 更新 `model-recipes.md` / `innovation-playbook.md`。
- **写作维度**：摘要哪段被批评？哪里降重没过？→ 更新 `paper-quality-gate.md`。
- **协作维度**：时间分配哪出问题了？谁负责什么？→ 更新 `timeline.md` 的节奏感。

## 二、四维复盘模板（赛后 48h 内填完）

### 1. 数据复盘
- 原始数据规模 / 质量如何？有哪些缺失、异常、重复？
- 清洗用了什么流程？哪一步最耗时 / 最坑？
- 有没有"以为能用、实际是坑"的字段或数据？
- **沉淀**：把可复用的清洗流程 / 函数写进 `preprocessing-pipeline.md` 或脚本。

### 2. 模型复盘
- 每题最终用了什么模型？效果（误差 / 指标）如何？
- 哪个模型是"看似高级、实际没用"？（淘汰，别下次再踩）
- 哪一步是亮点 / 创新？评委认了吗？
- 哪个假设被证明不合理？为什么？
- **沉淀**：把「题型 → 模型 → 效果」补进 `model-recipes.md`；把亮点套路补进 `innovation-playbook.md`。

### 3. 写作复盘
- 摘要 / 正文哪里被评委会挑刺？
- 降重 / 降 AI 味哪块没过？具体是哪些句子？
- 图表哪些被夸 / 被批（清晰度、信息量）？
- **沉淀**：把好的句式 / 结构补进 `bao-paper-writing.md`、`figures-and-abstract.md`；把踩坑补进 `writing-deai-dedup.md`。

### 4. 协作 / 节奏复盘
- 时间分配合理吗？哪个环节超时了？
- 定题拖到几点？红警线有没有守住？
- 队友分工顺畅吗？有没有沟通断裂？
- **沉淀**：把节奏教训写进 `timeline.md`，形成个人化版本。

## 三、资产沉淀清单（能留则留，别丢）

赛后整理出可复用资产，存进工作区对应目录：

| 资产 | 存哪 | 复用场景 |
|---|---|---|
| 复现脚本（种子固定、可跑） | `src/` / `scripts/` | 下次同型题直接改参数 |
| 图表样式（配色/字体/DPI） | `figures/style.py` | 所有题通用 |
| 参考文献库（已核验的） | `refs/` | 同类题直接引 |
| 项目骨架 | `init_project.py` 模板 | 每次开局 |
| 踩坑清单 | 复盘文件 | 下次避免 |
| 答辩被问倒的问题 | 复盘文件 | 下次提前准备 |

**原则**：可复用的沉淀成「脚本/样式/模板」，可避免的教训沉淀成「清单/规则」，别都堆在复盘文件里过期发霉。

## 四、复盘结果回流到 skill（让 skill 越长越强）

复盘发现的规律，**主动更新对应 reference 文件**，形成"用一次强一次"的闭环：
- 新题型 / 新模型 → `model-recipes.md` / `cases-<年>.md`
- 新亮点套路 → `innovation-playbook.md`
- 写作教训 → `bao-paper-writing.md` / `writing-deai-dedup.md`
- 节奏教训 → `timeline.md`
- 赛制变化 → `rules-and-deadlines.md` / `contests-catalog.md`

> 每次参赛 = 一次 skill 训练。打 3 次比赛，skill 就覆盖了你最常用的 90% 场景。

## 五、复盘工具：`review_survey.py`

运行 `python scripts/review_survey.py` 会：
1. 打印一份**四维复盘问题清单**（可逐条自答）；
2. 生成一个 `review_YYYY-MM-DD.md` 复盘草稿模板，直接往里填；
3. 提醒你把可复用资产/教训写进对应 reference 文件。

> 用法见 `scripts/review_survey.py` 首行注释。无第三方依赖，零安装即跑。
