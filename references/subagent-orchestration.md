# 子代理并行解题与交叉验证（实测经验，2024A 板凳龙全程验证）

> 来源：一次完整的 2024 国赛 A 题全流程求解中，用 20+ 个子代理并行跑"多方法求解 + 独立复核"。
> 下面每条都是踩过之后的结论，不是理论推测。**核心一句话：先自己写好核心模块再派发；必须有一条独立复核分支。**

## 一、什么时候值得开子代理

| 值得 | 不值得 |
|---|---|
| 同一问的**多种方法**并行（互证） | 单个小脚本（自己写更快） |
| **单分支分钟级以上**的扫描/优化 | 强依赖串行的任务 |
| 需要**独立实现**才有验证力 | 需要频繁看中间结果微调的探索性工作 |
| 主进程不能被阻塞（长任务） | 一句话能说清的一次性计算 |

## 二、最重要的一条：**先自己写好并冒烟测试"核心模块"，再派发**

- **反面实测**：直接让子代理"从零实现几何 + 求解"，3 个里有 2 个把预算烧在重复实现与调试上，
  最终 **"空手耗尽"（ran out of room）且没有任何产出文件**。
- **正面实测**：把可复用层抽成**一个核心模块文件**（自己写 + 冒烟测试：打印不变量/残差/边界），
  再在每个子代理提示里写明"**直接 import `<core>`，不要重写几何、不要探索**" →
  Q3 第二轮 6 个子代理 5 个一次成功，Q4 五路全部交付。
- **核心模块该包含什么**：几何/物理的**唯一真值实现**、常量、以及 `__main__` 里的**自检**
  （例如：起点是否落在理论位置、约束残差量级、边界处是否 C¹ 连续）。
  （本次做法：把"螺距参数化几何 + 链条弦长定位 + 碰撞判定"抽成一个核心模块文件，各分支只 import 它。）

## 三、提示词模板（实测有效的八个要素）

1. **一句话任务** + 明确"聚焦、**直接写脚本跑**、不要长篇探索"
2. **现成模块清单**：函数签名 + 返回含义 + 已验证的不变量
3. **背景事实与已验证基准数值**（便于它们自查，也便于你事后对账）
4. **逐步清单（1/2/3…）**，不要开放式提问
5. **唯一输出文件名**（问题名 + 分支名作前缀的 txt 日志），避免互相覆盖
6. **固定上报格式**（4–6 项），便于汇总成表
7. **明确"不要改哪些文件"**
8. **已知环境坑**（例：本机 multiprocessing 不可用、`scipy.optimize.shgo` 在 numpy 2.x 崩）

## 四、必须有一条"独立复核"分支（本次最大收益）

- **实测**：独立复核分支抓出了主分支的**两个真实交付缺陷**——`result1/2/4.xlsx` 的
  **行位整体上移一行 + 列位整体左移一列**（覆盖表头、末行/末列空、标签被数值覆盖）。
  主分支自检"全绿"，因为自检用的是**同一套错误约定**。
- **铁律**：复核分支必须用**不同方法 / 不同库 / 不同参数化**重算，**不得调用被核对象的函数来自证**。
- **复核清单**（照抄可用）：
  1. 解析解的唯一性（例：把相切条件写成方程组，检查有几个代数解、哪一个物理有效）
  2. 关键量逐位对比（坐标/速度/参数的最大绝对差）
  3. 不变量与约束残差（弦长、刚杆、守恒、边界 |
     例：残差应 ~1e-12 而非 1e-3）
  4. **交付物格式**（Excel 行列位、文件命名、位数）——最容易翻车且最容易被自检放过

## 五、常见失败模式与处置

| 失败模式 | 现象 | 处置 |
|---|---|---|
| **空手耗尽** | 关闭消息为空、无任何产出文件 | 重开，提示词改成"现成模块 + 明确步骤" |
| 崩溃但有输出 | 输出文件里有 traceback | **先读文件**（常能拿到部分结论），再决定重跑 |
| 慢到不可用 | 单配置 47 ms × 数千配置 = 小时级 | 剪枝候选集、换光滑判据、砍配置数 |
| 自报不可信 | 自检"全绿"但与独立分支矛盾 | **一切数字以独立复算为准** |
| 进程失控 | 代理已死，python 仍在跑（CPU 上千秒） | `Get-Process python` 查，终止孤儿进程 |
| 结果互相覆盖 | 两个分支写同一路径 | 分配唯一文件名；同一路径并发写会锁文件 |
| **通配误删他人文件** | 子代理清理自己的临时探针时用 `solve\_*.py` 之类通配，**误删了主进程与其他分支的同前缀脚本**（本次实测：3 个文件被删，且项目无 git、无法回滚） | **提示词必须写明**："只删你自己创建的文件，**禁止通配符删除**；清理前列出将删清单并逐个确认"。**并且项目一开工就 `git init`**（工作区内的小仓库即可）——本次正因为没有版本库，损失只能靠重建 |
| 中间失败输出被当成终局 | 分支"先跑出一版未收敛结果"，据此下了结论，随后分支重跑结论反转 | 见第七节第 5 条：**判定成功/失败前先确认分支已结束，并读它的收敛性/可行性证据** |

## 六、并行度与资源（本机实测）

- **multiprocessing 不可用**：沙箱拒绝命名管道，`Pool` 抛 `PermissionError(13, '拒绝访问')`。
  → 阶段内**不要**用 Pool；并行靠"开多个子代理"或"后台作业"。
- **不要和脚本抢同一个文件**：`Out-File -FilePath X` 重定向 + 脚本自身也写 `X` → `PermissionError`。
  重定向路径与脚本内部日志路径必须分开。
- 长任务放**后台作业**（`run_in_background`），主进程继续做别的（写文档/做下一分支）。

## 七、汇总纪律（收到分支结果之后）

1. **先并排对照**：同一量的多值 + 各自判据 + 是否独立复核，列成一张表再下结论。
2. **分歧先问"是不是在算同一个量"**：实测三法给出 0.4443 / 0.4596 / 0.527 的差异，
   根因是**判据不同**（端点快照 / 全程首个碰撞 / 解析界），不是谁算错了。
3. **光滑判据优先于跳变判据**：若某量在真值附近**不连续**（例："首次碰撞半径"在板对切换处跳变），
   对它做插值/二分必偏；应改造成**连续量**（例：`min_r C(p,r) - 阈值`）再求根 —— 本次据此把
   答案从 0.46048（跳变插值）纠正到 0.46060（光滑求根，残差 1e-12）。
4. **结论必须标注"谁独立验证过"**：论文/交付里写清哪些数字有第二来源。
5. **绝不用分支的"中间失败输出"下结论——必须等它的最终结果**。本次真实翻车：某分支先跑出一版**未收敛**的结果
   （优化器给出 99.97 m 的退化解，还自相矛盾地写"明显更短"），我据此判定该分支"失败、结论无效"，
   并向用户报告了"四路一致：不能变短"；该分支随后重跑收敛，**结论恰好相反**（同曲率限制下可短 16.8%），
   我不得不回头更正。**规则**：分支的产出文件可能被重写；判定"成功/失败"前先确认它**已结束**，
   且要读它的**收敛性/可行性证据**（残差、margin、N 收敛表），而不是只看结论行。
6. **解释边界必须显式写出**：同一提问在不同解释下答案可能相反。本次"能否调整圆弧使调头曲线变短"——
   在两段圆弧族内答案是**不能**（长度被几何唯一锁定），允许改变曲线形式则答案是**能**（短 16.8%）。
   报告与论文都要**两个都写**，并写清各自的前提；只写一个等于押注读者的理解。
7. **子代理的"一句话结论"要能与它自己的数字对账**：见到"明显更短"却给出更大的数值，直接判为无效并要求重跑。

## 八、子代理 vs 后台作业 vs 主进程（本次实际选择）

| 场景 | 选择 | 理由 |
|---|---|---|
| 多方法求解同一问 | **多个子代理**（3–6 个） | 天然并行、可独立实现 |
| 独立复核 | **单独子代理** | 必须换方法重算 |
| 长扫描（分钟~小时级） | **后台作业** | 不阻塞主进程 |
| 核心模块编写与冒烟 | **主进程亲自做** | 是全流程的真值基准 |
| 交付物最终验收 | **主进程亲自做** | 复核结论要自己抽样确认 |
