# 逐段核验原则（核验防漏 · 上下文有限下的排查纪律）

> 定位：把成品（论文 / 最终方案 / 数据清单 / 代码）丢给模型核验时，**禁止"整篇通读、一次性找全部问题"**。
> 模型上下文有限——一口气检查整篇论文 = 前面逐条认真、后面走马观花，token 一长还会截断漏尾，
> 核验清单一长更是必漏。正确姿势是：**选一条主线 → 切成段 → 一段一段闭环排查**，一段没核 = 没核完。

## 一句话原则

**不整篇核验，分段闭环排查；选主线、给分段清单、逐段查、一段不核 = 未完成。**

## 三步法

### 第一步 · 选主线（一次只走一条）

核验前先定一条主线，不要同时查好几样。常用主线：

| 主线 | 适用 |
|---|---|
| **论文正文** | 交稿前全文核验（最常见） |
| **最终方案** | 只核模型与结果的方案一致性 |
| **数据清单** | 数据完整性复核（与 `data_inventory.md` 配套） |
| **代码 / 求解脚本** | 复现性核验 |

### 第二步 · 切分段（先列"分段清单"再动手）

把主线切成若干段，**先把分段清单列出来**，再逐段查。论文正文的推荐分段（对应 `paper-quality-gate.md` 关卡）：

1. 摘要（四要素 + 数字 + 与正文一致）
2. 问题重述与问题分析
3. 模型假设与符号说明
4. 各问模型建立与求解（每问单独一段）
5. 模型检验与灵敏度
6. 模型评价与推广
7. 结论
8. 参考文献（铁律一：逐条真实 + 一一对应）

### 第三步 · 逐段闭环（每段 = 固定清单 → 排查 → 记录 → 确认）

每一段都走闭环，不跳过：

1. **该段固定核验清单**：对照 `paper-quality-gate.md` 对应关卡 / 收口项，每段要查的点是**固定且已知的**，不临场发挥；
2. **排查**：只查这一段，查出问题记入 `out/verification_log.md`（哪一段 / 什么问题 / 建议改法）；
3. **记录确认**：该段全部问题记录完，确认"这段查干净了"，才进下一段。

> 问题必须落盘到 `verification_log.md`——否则"查完忘了改 / 改完忘了复查"两件事都会发生。

## 分段自查（防漏的最后一道）

整条主线核完，回查三件事，缺一即未完成：

- [ ] **分段清单 vs 主线实际**：列出的每一段都实际核过了吗？（论文 8 段逐项打勾）
- [ ] **问题闭环**：`verification_log.md` 里的每条问题都有处理结果（已改 / 已确认不改+理由）吗？
- [ ] **跨段一致性单独过**：同一数字在摘要 / 正文 / 结论 / 图注是否一致——这是**最后单独做**的一步，
      不是每段顺手带过（`scripts/crosscheck.py` 专门干这个，别靠肉眼）。

## 与现有工具衔接

| 核验段 | 工具 |
|---|---|
| 摘要 / 正文数字 vs results.json | `check_results.py`（野数字） |
| 跨段数字一致性 | `crosscheck.py`（19.43 vs 19.5） |
| 参考文献逐条真实 + 对应 | `verify_refs.py` + `ref_search.py` |
| 量纲 / 量级 / 边界 | `sanity_check.py` |
| 降 AI 味 / 降重 | `dedup_scan.py` |
| 数据完整性（清单对照） | `data_profiler.py --inventory` |

## 常见翻车（每条都是真实教训）

| 场景 | 后果 | 正确做法 |
|---|---|---|
| 整篇论文一次性"通读找问题" | 前半逐条、后半应付，后段必漏 | 先给分段清单，逐段闭环 |
| token 超长被截断 | 后半段根本没核 | 分多次、每段单独给（一次只丢一段进上下文） |
| 核验清单 20 条一口气列 | 逐条打勾变成走过场 | 每段 3–5 条固定项，逐段给 |
| 查完不记录 | 改完忘了复查 / 改了这处漏了那处 | 问题落盘 `verification_log.md` |
| 不查跨段一致性 | 摘要写 19.43、正文写 19.5 没人发现 | 最后单独跑 `crosscheck.py` |
